# Storage

Contents of `packages/storage`; the rules are in packages/CLAUDE.md and the root CLAUDE.md. Keep this list current when you add or change a file here.

- projects kept in the browser. `store.ts` (`projectStore(kv, readers, now)`: list, open, save, remove; each project is `project/<id>`, its exact .spindlelabs.json text, and `summary/<id>`, name and save time; open goes through `projectFromJson`; a save given the save time it expects is refused with `ProjectChangedError` when another tab saved since) over the `KeyValue` interface in `key-value.ts` (`memoryKeyValue()` for unit tests); `indexeddb.ts` is the thin browser adapter, checked by `apps/fission/e2e/storage.mjs`; `localStore(readers)` is the two together; `autosave.ts` (`startAutosave`: saves a quiet moment after each `changed()`, one save in flight, reports "saving"/"saved"/error; given `storedAt`, each save expects the store to hold its last read or write, so a stale tab says "changed in another tab" instead of overwriting, and its `leaving()` asks rather than journal a change that would be put back over the other tab's; tested on a fake clock; `leaving()`, called by the shell when the page is hidden, reloaded or closed, writes changes not stored yet to the journal and starts the save at once, false when it can't keep them so the page asks before going); `unsaved.ts` (the unsaved-changes journal in localStorage, `panoshape.unsaved/<id>` holding `@<ms>` (when it was written; `@<ms>!` for one recovery couldn't store, which no tab saves over), a newline and the file text, removed once the store holds that state or newer; `recoverUnsaved` puts entries back before the app lists projects, skipping one older than the stored project's save time (the time its state was read); seeded page-life runs in `test/unsaved.test.ts`, two tabs sharing one store and journal in `test/two-tabs.test.ts`, review repros in `test/review-repros.test.ts`). Workspaces call `ctx.projectChanged()` after writing `ctx.project`; the shell autosaves on it.
- `reopen.ts`: the reopen guard (audit S2): the `panoshape.opening` mark in localStorage names the project a tab is opening until it settles (SETTLED_MS after showing); a visit finding it skips that project once. `check()` first asks the other tabs over a BroadcastChannel (`OpeningChannel`), so a tab still opening it answers within ASK_MS and isn't taken for a freeze (real-use hunt A3); `finished()` clears only the tab's own mark. Tested on a fake clock and bus in `test/reopen.test.ts` (seeded one-tab and two-tab runs against a model); browser check `apps/fission/e2e/reopen.mjs`.
