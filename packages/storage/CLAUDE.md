# Storage

Contents of `packages/storage`; the rules are in packages/CLAUDE.md and the root CLAUDE.md. Keep this list current when you add or change a file here.

- projects kept in the browser. `store.ts` (`projectStore(kv, readers, now)`: list, open, save, remove; each project is `project/<id>`, its exact .spindlelabs.json text, and `summary/<id>`, name, save time and save number (`order`, counted across every project in one `order` entry, so the list is in the order saves happened whatever the clock said, real-use hunt B5, `test/clock-order.test.ts`); open goes through `projectFromJson`; a save given the save time it expects is refused with `ProjectChangedError` when another tab saved since; the check and both writes are one `KeyValue.update`, one readwrite IndexedDB transaction, so no other tab's save lands between them and a killed tab leaves both entries or neither, real-use hunt B6/B7, `test/store-atomic.test.ts`; `storedCopy(store, project)` finds the stored project holding exactly an opened one, compared as read, so Open reuses it instead of storing another copy, real-use hunt B3, `test/stored-copy.test.ts`) over the `KeyValue` interface in `key-value.ts` (`memoryKeyValue()` for unit tests); `indexeddb.ts` is the thin browser adapter, checked by `apps/fission/e2e/storage.mjs`; `localStore(readers)` is the two together; `autosave.ts` (`startAutosave`: saves a quiet moment after each `changed()`, one save in flight, reports "saving"/"saved"/error; given `storedAt`, each save expects the store to hold its last read or write, so a stale tab says "changed in another tab" instead of overwriting, and its `leaving()` asks rather than journal a change that would be put back over the other tab's; tested on a fake clock; `leaving()`, called by the shell when the page is hidden, reloaded or closed, writes changes not stored yet to the journal and starts the save at once, false when it can't keep them so the page asks before going); `unsaved.ts` (the unsaved-changes journal in localStorage, `panoshape.unsaved/<id>` holding `@<ms>` (when it was written; `@<ms>!` for one recovery couldn't store, which no tab saves over), then `~<ms>` when the tab knew it (the save time of the stored state the change was made from), a newline and the file text, removed once the store holds that state or newer; `recoverUnsaved` puts entries back before the app lists projects, skipping one older than the stored project's save time (the time its state was read); one naming the state it was made from goes back only over that state (`store.save`'s `unchangedSince`), and over any other, a stale tab's change, is stored as a separate project named `fromAnotherTab` ("Box (from another tab)") listed behind every other (`save`'s `behind`), so the newer work still opens, and a save never removes such an entry (real-use hunt S1, `test/two-tabs.test.ts`); an entry from a newer SpindleLabs (`NewerFormatError`, core) is moved to `panoshape.unsaved-newer/<id>` (`NEWER_PREFIX`), out of this build's autosave's way, said once, and put back by a build that reads it (real-use hunt S2, `test/unsaved.test.ts`); `keptEntry` gives an entry recovery couldn't store (storage full), which the app opens instead of the older stored state, with an autosave started `fromKept` that owns the entry: it saves over the older state once there is room and journals each state still marked kept until then (real-use hunt B1, `test/kept-entry.test.ts`); seeded page-life runs in `test/unsaved.test.ts`, two tabs sharing one store and journal in `test/two-tabs.test.ts`, review repros in `test/review-repros.test.ts`). Workspaces call `ctx.projectChanged()` after writing `ctx.project`; the shell autosaves on it.
- `persist.ts`: `keepStorage(navigator.storage)` gives a function that asks the browser once to keep the store (`persist()`), so projects aren't cleared when space runs low; the shell calls it after the first save of the user's own work, never on load (real-use hunt B3, `test/stored-copy.test.ts`).
- `reopen.ts`: the reopen guard (audit S2): the `panoshape.opening` mark in localStorage names the project a tab is opening until it settles (SETTLED_MS after showing); a visit finding it skips that project once. `check()` first asks the other tabs over a BroadcastChannel (`OpeningChannel`), so a tab still opening it answers within ASK_MS and isn't taken for a freeze (real-use hunt A3); `finished()` clears only the tab's own mark; `putAway()`/`back()` (page hidden or frozen, then shown again) take the tab's mark down so a phone killing a put-away tab leaves none (D1), putting it back while the project is still opening. Tested on a fake clock and bus in `test/reopen.test.ts` (seeded one-tab and two-tab runs against a model); browser check `apps/fission/e2e/reopen.mjs`.
