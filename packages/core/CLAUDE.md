# Core: document model and kernel bridge

Contents of `packages/core`; the rules are in packages/CLAUDE.md and the root CLAUDE.md. Keep this list current when you add or change a file here.

- The shared document model and the kernel bridge.
- `src/kernel/`:
  - `kernel-client.ts` is the only way the app talks to the kernel (`kernel.call(op, ...args)` returns a promise; add new ops to `KernelOps`, `entry-points.ts` and the worker's `ops` table). A failed call rejects with a `KernelError`: the kernel's `message`, plus `kind` and `inputs` (which input is at fault) to decide by; `kernelFailure` turns anything thrown into that plain data for the trip from the worker. The body store ops (`body_build`, `body_view`, `body_stl`, `body_free`, `body_count`) keep bodies in the worker's kernel by handle (24c+); `body_hide` lets a body's display mesh go until `body_view` shows it again, and `body_boolean(target, tools, op)` gives the results' handles and where their faces and edges came from, by the app's handles (35d). A started kernel (the worker's `ready`) that crashes is replaced as a trapped one is (`KERNEL_RESTARTED`); each call has a time limit (step 35d3, `time-limit.ts`), and one past it (stuck, or a worker the browser closed) fails alone as kind "timed-out" (`KERNEL_TOOK_TOO_LONG`) and its kernel is replaced, the other calls waiting failing with `KERNEL_STOPPED_FOR_ANOTHER`; the download and calibration are never timed (B2b).
  - `time-limit.ts`: each call's time limit (35d3): its size in calibration units (a boolean's face pairs, a build's profile corners, a body's mesh, a sketch's curves, a slice's triangles × layers), times the ms a unit takes on this device (the worker's calibration boolean, `ready.unitMs`), times HEADROOM 4, never under LIMIT_FLOOR_MS (10 s). The costs per unit are measured on the shipped build (the comments give the numbers). `test/time-limit.test.ts` by hand; the client's timing in `test/kernel-client.test.ts`.
  - `kernel.worker.ts` runs the WASM kernel in a Web Worker.
  - `kernel-types.ts` holds the shapes of kernel results and inputs (`BodyHandle`, `KernelFailure` with `KernelErrorKind` and `KernelInput`; `Outline`, the kernel's `ProfileIn`; `SketchLine` and `SketchOutline` for the sketch ops `snap_to_grid` and `sketch_outline`, step 21a).
  - `wasm/`: the private kernel's release build, committed (`fission_kernel.js`, its `.wasm`, types, `kernel.json`, `crates.json`, `LICENSE-KERNEL.txt`); only the kernel's Release pull requests change it. To try an unreleased kernel locally, build it over these files from a kernel checkout (the kernel repo's CLAUDE.md) and never commit that.
  - `handshake.ts`: `startKernel` calls the build's `begin` with the app's key (`kernel-key.ts`'s `KERNEL_KEY`) before any other call and refuses a build that doesn't take it; the worker and `node-kernel.ts`'s `loadKernel` both use it. Since 2026-10-29 the key is in none of the files in `wasm/` (kernel.json has only its `handshake_sha256`), so those files alone don't start. `test/handshake.test.ts`.
  - `kernel-key.ts`: the release's handshake key, written by the kernel's Release workflow with each build; never edit by hand (`check_kernel_build.py` checks it hashes to kernel.json's `handshake_sha256`).
  - `entry-points.ts`: the build's entry points under the app's op names. The build exports each under a fixed meaningless label (copy protection), so this table is the one place that maps them; the worker, `node-kernel.ts` and the baseline call through it. A new kernel op brings a new label here.
- `src/model/` (see docs/integration.md), built:
  - `project.ts`: format version and migrations, `projectToJson`/`projectFromJson`: the .spindle file; a file (or a workspace's part) from a newer SpindleLabs is refused as a `NewerFormatError`, so the unsaved-changes journal keeps it (real-use hunt S2).
  - `representation.ts`: the representation registry (producers, converters, and the file importers: `registerImporter`/`importerFor`, one per format).
  - `actions.ts`: the one action registry: verbs per selection kind and representation; `ctx.actions`.
  - `feature.ts`: intent, provenance, timeline.
  - `graph.ts`: dependencies, staleness, `path` (the shortest chain), `onChange`.
  - `downstream.ts`: downstream summaries: what another workspace makes from the design, its state from the graph; the chips in Design's properties panel.
  - `change-notes.ts`: change notes: one dismissible note per result another workspace's change updated, naming the cause, with the dependency chain from `graph.path`; `onChange` tells the shell to redraw. On `WorkspaceContext` as `changeNotes`: whoever calls `graph.changed`/`remove` for a user's edit records it there with the cause's words.
  - `files.ts`: files dropped or pasted (X6a): `identifyFile` by contents and name, `FILE_FORMATS` (each format's representation and who will take it), `routeFiles` through the registered importers; a workspace opens a format by `registry.registerImporter` in its `registerRepresentations`.
  - `svg.ts`: `outlineToSvg`: an Outline as an SVG file in mm (one path, holes by evenodd, y flipped, arcs as quarter turns at most so rounding never moves a centre, the viewBox the exact box); Design's Copy as SVG writes it.
  - `links.ts`.
  - `ownership.ts`: one owner per linked value: `proposeEdit`, `acceptProposal`/`rejectProposal`, `setOwnedValue`, `transferOwnership` (its `label` names the undo step the hand-over is stored in).
  - `overlay.ts`.
  - `workspace.ts`: the public Workspace API; `mount` returns a `MountedWorkspace` (`sleep`, `wake`, `unmount`: workspaces stay warm, X7; `run`: does one of its commands as its own buttons would, how the AI assistant applies an accepted change, AI2; `aiView`: what the assistant is told before a request, `AIView`, 25c3; `fileEntries`: its New and exports in the top bar's File ▾, `FileEntries`, U0f2a).
  - `shortcuts.ts`: the one shortcut table (X7b): `ShortcutTable` (the shell's `SHELL_SHORTCUTS` and each plugin's `shortcuts`), `parseChord`/`chordOf`/`chordLabel`, `lookup` (pane in use, other pane, shell), `clashes` (same key or id in one scope, a workspace key the shell uses, `BROWSER_RESERVED`), `help` (the list's order). Workspaces run theirs in `MountedWorkspace.shortcut`.
  - `session.ts`: `createSelection`, the one selection; `historyNotBuilt`, a history that throws, for tests of workspaces that never undo.
  - `history.ts`: `createHistory`, the one undo/redo history of whole-project snapshots (labels, merge keys, limit, `reset` on open; step 20a; `amend` takes a default filled in while mounting into the present, 20b; `step(label, run)` makes many changes one labelled step, all or nothing, and `restoring()` tells a mount it is an undo's, 20c). `WorkspaceContext.projectChanged(label, mergeKey)` records a step.
- `src/print/` (Slice H2): `gcode.ts`, the G-code replayer (P0a; `@fission/core/gcode`, re-exported by packages/testing for its checks); `playback.ts`, the print preview's clock: `playback` lays a slice's G-code out as straight pieces in printing order (arcs cut into 5° pieces), each with its start and finish on the replayer's clock, plastic or not, its kind from `;TYPE:` (`kindOf`, `PRINT_KINDS`), its width from its volume as a printed bead (rectangle with half-round sides), and the layers; `momentAt` (the piece running at a second, how far along, the nozzle, the plastic laid), `layerDone` (a layer's last second, so the layer slider and the time-lapse share one clock). Tested in `test/print-playback.test.ts` (two layers by hand, a half-turn arc, planted bugs caught).
- `src/model/`, DRAFT: `material.ts`, `machines.ts`, `search.ts`, `feedback.ts`, `parameters.ts`, `references.ts`, `viewport.ts`.
