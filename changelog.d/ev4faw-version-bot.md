- Version numbers are now given when a change reaches `main`, not picked by the pull request. Each pull request adds its entry as a file of its own in `changelog.d/` (first line `fix`, `step N` or `none`, then the entry), and `.github/scripts/changelog.py` numbers the entries by the order their pull requests merged (main's first-parent history: one merge commit per pull request), so two pull requests in the merge queue can no longer conflict over CHANGELOG.md and VERSION, renumber and run CI again (#349 was dropped from the queue five times this way). `VERSION` is gone: `changelog.py version` works it out, `changelog.py show` prints the whole numbered changelog, and `changelog.py fold`, a small pull request of its own now and then, writes the entries into CHANGELOG.md without changing any number. CI checks every fragment's form and that a pull request adds exactly one fragment (or folds), never changes a merged one and never writes a version heading itself. Checked by hand-worked numberings, 500 seeded random merge orders (no number ever repeated or skipped, every entry once, folding at any point giving the same numbers), real git histories with merge commits (including a branch that merged main in), and planted bugs each caught.
